# V0.1 Refactoring — 멀티파일 구조

## 목표

기존 단일 `lolreview.c`를 책임별 모듈로 분리하고, Beej's Guide to C Ch.13~17에서 학습한 Scope, Header File, Multi-File Project, Object File, Linking 개념을 적용한다.

기존 V0.1의 기능과 출력은 그대로 유지한다.

## 프로젝트 구조

```text
main.c
event.c / event.h
analysis.c / analysis.h
output.c / output.h
```

각 모듈의 역할:

* `main.c` → 전체 프로그램 흐름 관리
* `event.c` → 파일 입력, Event 생성 및 메모리 관리
* `analysis.c` → 통계 계산 및 Critical Moment 탐지
* `output.c` → 분석 결과 및 이벤트 출력

전체 데이터 흐름:

```text
match.txt
    ↓
load_events()
    ↓
Event *events
    ↓
analyze_events()
    ↓
MatchAnalysis
    ↓
print
    ↓
free
```

## 적용한 내용

* `.h` / `.c` 파일 분리
* Include Guard 적용
* 구조체를 이용한 분석 결과 관리

* `.c → .o` 개별 컴파일

* 기존 V0.1 기능 및 출력 유지

## 이번에 헷갈렸던 내용

* 구조체 변수는 `.`, 구조체 포인터는 `->`를 사용한다.

```c
result.critical_count;
result_ptr->critical_count;
```

* 동적 구조체 배열은 다음과 같이 접근할 수 있다.

```c
result.moments[i].start_time;
```

* `char[]` 배열끼리는 `=`로 문자열을 복사할 수 없다.

```c
strcpy(result.moments[i].object, events[j].event);
```

* 구조체 포인터와 배열 접근 표현
moments->start_time
= moments[0].start_time
= (*moments).start_time

moments[i].start_time
= (*(moments + i)).start_time
= (moments + i)->start_time 

* `realloc()` 실패 시 기존 메모리는 자동으로 해제되지 않는다.

* `free()` 이후 포인터가 자동으로 `NULL`이 되지 않으므로 필요하면 직접 초기화한다.

```c
free(result->moments);
result->moments = NULL;
```

* 함수에서 생성한 동적 메모리를 반환하면 이후 해제 책임을 호출자가 가질 수 있다.

* Header File은 별도의 Object File로 컴파일되지 않는다.

```text
.h → 선언 및 타입 공유
.c → 구현
.o → 컴파일된 코드
Linking → 여러 .o 연결
```

* 함수 선언 문제는 Compile 단계, 구현을 찾지 못하는 문제는 Link 단계에서 발생한다.

* argv[1]은 char *이고 파일 이름 문자열을 가리킨다. *argv[1]은 첫 번째 문자 하나이다.
fopen(argv[1], "r");   // correct
fopen(*argv[1], "r");  // wrong

* 포인터를 통해 호출자의 count를 증가시킬 때 괄호가 필요하다.
(*count)++;   // increase the value
*count++;     // equivalent to *(count++)

* free() 이후 포인터가 자동으로 NULL이 되는 것은 아니다.
free(result->moments);
result->moments = NULL;
