## 0026. Remove Duplicates from Sorted Array (26.8.2)

### 유형

* Array
* Two Pointers

### 처음 풀이

* `erase()`를 이용하여 중복 원소 삭제
* O(n²)

### 최적 풀이

* Two Pointers
* O(n)

### 핵심 아이디어

* `fast` 포인터는 배열을 끝까지 탐색한다.
* `slow` 포인터는 중복이 제거된 원소를 저장할 위치를 가리킨다.
* `nums[fast] != nums[fast - 1]`이면 새로운 원소이므로 `nums[slow] = nums[fast]`를 수행하고 `slow`를 증가시킨다.
* 배열의 앞부분(`0 ~ slow-1`)에 중복이 제거된 결과가 저장된다.

### 배운 점

* `vector::erase()`는 인덱스가 아닌 **iterator**를 인자로 받는다.
* `erase()`는 뒤의 원소를 모두 앞으로 당기므로 한 번 호출할 때 O(n)이 걸린다.
* 정렬된 배열에서 중복 제거는 **투 포인터**를 사용하면 O(n)에 해결할 수 있다.
* 투 포인터는 읽는 위치(`fast`)와 쓰는 위치(`slow`)를 분리하여 사용하는 대표적인 기법이다.


## 0027. Remove Element (26.8.3)

### 유형

* Array
* Two Pointers

### 처음 풀이

* `vector::erase()`를 이용하여 `val`과 같은 원소를 삭제
* 삭제 후 인덱스가 당겨지므로 `i--` 수행
* O(n²)

### 최적 풀이

* Two Pointers
* O(n)

### 핵심 아이디어

* `fast` 포인터는 배열을 끝까지 탐색한다.
* `slow` 포인터는 삭제하지 않을 원소를 저장할 위치를 가리킨다.
* `nums[fast] != val`이면 삭제 대상이 아니므로 `nums[slow] = nums[fast]`를 수행하고 `slow`를 증가시킨다.
* `nums[fast] == val`이면 건너뛴다.
* 배열의 앞부분(`0 ~ slow-1`)에 삭제되지 않은 원소들이 저장된다.
* 문제에서 **앞의 `k`개 원소만 올바르면 되고, 그 이후의 값은 상관없다.**는 조건이 있기 때문에 뒤의 원소를 실제로 삭제할 필요가 없다.

### 배운 점

* `vector::erase()`는 원소를 삭제하면서 뒤의 원소를 모두 앞으로 이동시키므로 한 번 호출할 때 O(n)이 걸린다.
* 반복문 안에서 `erase()`를 여러 번 호출하면 전체 시간복잡도는 O(n²)이 된다.
* 배열에서 특정 원소를 제거할 때는 **삭제하는 것이 아니라, 남길 원소를 앞쪽으로 덮어쓰는 방식**을 생각하면 투 포인터를 떠올리기 쉽다.
* 투 포인터는 읽는 위치(`fast`)와 쓰는 위치(`slow`)를 분리하여 사용하는 대표적인 기법이다.
* 문제에서 **"in-place"**, **"앞의 k개만 올바르면 된다"** 와 같은 조건이 나오면 투 포인터를 먼저 고려하는 습관을 들이자.


## 0088. Merge Sorted Array (26.8.3)

- Two Pointers

- 일부 테스트 케이스만 통과
- nums2의 정렬이 깨지는 반례 존재

### 최적 풀이
- Two Pointers
- O(m + n)

### 핵심 아이디어
- nums1과 nums2의 **뒤에서부터** 비교한다.
- 더 큰 값을 nums1의 뒤쪽부터 채운다.

## *0121. Best Time to Buy and Sell Stock (26.8.4)

### 유형

* Array
* Greedy (현재 최선의 선택 유지)
* One Pass (한 번 순회로 해결)
* Prefix Minimum (누적 최솟값)

### 처음 풀이

* 모든 `(사는 날, 파는 날)` 조합을 이중 반복문으로 탐색
* 가능한 모든 경우를 비교하여 최대 이익 계산
* 정답은 맞지만 시간 복잡도가 `O(n²)`이라 시간 초과(TLE)

### 최적 풀이

* Greedy + One Pass
* `O(n)`

### 핵심 아이디어

* **지금까지의 최저 가격(`minPrice`)**을 계속 저장한다.
* 매일 **오늘 판다면 얼마의 이익을 얻을 수 있는지** 계산한다.
* `price - minPrice`가 현재 최대 이익보다 크면 갱신한다.
* 이후 오늘 가격이 더 낮다면 `minPrice`를 갱신한다.

### 배운 점

* 브루트포스에서 **필요한 정보만 상태(State)로 유지**하면 시간 복잡도를 크게 줄일 수 있다.
* 과거의 모든 가격을 다시 볼 필요 없이 **지금까지의 최솟값 하나만 기억하면 된다.**
* Greedy 문제에서는 "현재 시점에서 가장 좋은 선택"을 유지하는 것이 핵심이다.
* `1e9`와 같은 큰 값을 초기 최솟값(INF)으로 사용할 수 있으며, `prices[0]`으로 초기화하는 방법도 자주 사용된다.
* 이중 반복문을 작성했다면 **안쪽 반복문에서 필요한 정보를 하나의 변수로 압축할 수 있는지** 먼저 생각해 보는 습관이 중요하다.

### Greedy 핵심 요약

* **정의**: 매 순간 최선의 선택을 하는 알고리즘.
* **조건**: 현재 최선의 선택이 전체 최적해로 이어져야 한다.
* **판단법**:

  1. 현재 최선의 선택이 명확한가?
  2. 그 선택이 나중에도 손해가 되지 않는가?
* **대표 예시**: Best Time to Buy and Sell Stock → **지금까지의 최저가만 유지**한다.


# 0169. Majority Element (26.8.5)

### 유형

* Array
* Hash Table
* Sorting
* Boyer–Moore Voting Algorithm
* Greedy (상쇄(Canceling) 아이디어)

### 처음 풀이

* `unordered_map`을 사용하여 각 숫자의 등장 횟수를 저장
* 가장 많이 등장한 원소를 찾아 반환
* 시간 복잡도는 `O(n)`이지만 해시맵을 사용하므로 공간 복잡도는 `O(n)`

### 최적 풀이

* Boyer–Moore Voting Algorithm
* `O(n)` / `O(1)`

### 핵심 아이디어

* **현재 후보(`candidate`)**와 **후보의 우세 정도(`count`)**만 유지한다.
* 현재 숫자가 후보와 같으면 `count++`
* 현재 숫자가 후보와 다르면 `count--`
* `count == 0`이 되면 지금까지 후보와 다른 숫자가 서로 상쇄된 것이므로 다음 숫자를 새로운 후보로 선택한다.
* 문제에서 **다수 원소가 반드시 존재한다고 보장**되므로 마지막 후보가 정답이다.

### 다른 풀이

#### 1. Hash Table

* 각 숫자의 등장 횟수를 저장
* 가장 많이 등장한 숫자를 반환

시간 복잡도

* `O(n)`

공간 복잡도

* `O(n)`

---

#### 2. Sorting

* 배열을 정렬한다.
* 다수 원소는 반드시 절반보다 많이 등장하므로 정렬 후 가운데 원소가 항상 다수 원소가 된다.

```cpp
sort(nums.begin(), nums.end());
return nums[nums.size() / 2];
```

시간 복잡도

* `O(n log n)`

공간 복잡도

* 정렬 알고리즘에 따라 `O(log n)` 또는 `O(1)`

### 배운 점

* 빈도수를 구하는 문제에서는 **Hash Table**을 가장 먼저 떠올리는 습관이 중요하다.
* **절반보다 많이 등장한다**는 조건은 매우 강력한 힌트이며, Boyer–Moore 알고리즘을 적용할 수 있는 신호이다.
* Boyer–Moore는 후보와 다른 숫자를 하나씩 **상쇄(Canceling)** 해도 다수 원소는 마지막까지 남는다는 아이디어를 이용한다.
* `count`는 현재 후보가 다른 숫자보다 얼마나 우세한지를 나타낸다.
* `count == 0`이면 후보와 다른 숫자가 모두 상쇄되었으므로 새로운 후보를 선택하면 된다.
* 정렬 후에는 **가운데 원소가 항상 다수 원소**라는 성질도 자주 사용되는 풀이이다.

### Boyer–Moore 핵심 요약

* **정의**: 다수 원소와 다른 원소를 하나씩 상쇄하여 최종 후보를 찾는 알고리즘.

* **유지하는 상태(State)**

  * `candidate` : 현재 다수 원소 후보
  * `count` : 후보의 우세 정도

* **동작 과정**

  1. `count == 0`이면 현재 숫자를 후보로 선택
  2. 후보와 같으면 `count++`
  3. 후보와 다르면 `count--`

* **시간 복잡도**: `O(n)`

* **공간 복잡도**: `O(1)`

### 기억할 패턴

* **빈도수 문제** → Hash Table
* **정렬 후 가운데가 답인지 확인**
* **"절반 초과" + `O(1)` 공간 요구** → Boyer–Moore Voting Algorithm을 의심한다.
