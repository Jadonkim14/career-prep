# **0070. Climbing Stairs (26.9.4)**

**### 유형**

* Dynamic Programming(动态规划)
* Recurrence Relation(递推关系)
* Rolling Array(滚动数组)

**### 풀이**

* 처음에는 `1칸`과 `2칸` 이동의 개수를 정한 뒤, 각각의 순서를 조합하는 **조합(组合)** 방식으로 접근했다.
* `2칸 이동`의 개수를 `numof2`로 정하면 `1칸 이동`의 개수와 전체 이동 횟수를 구할 수 있고, `C(total, choose)`로 경우의 수를 계산할 수 있다.
* 하지만 조합을 계산할 때 분자 전체를 먼저 곱한 뒤 마지막에 나누는 방식으로 구현하면서 **Integer Overflow(整数溢出)**가 발생했다.
* 최종적인 문제 유형이 **Dynamic Programming(动态规划)**임을 확인하고 DP 방식으로 전환했다.
* `f(x)`를 `x`번째 계단까지 올라가는 방법의 수로 정의하면, 마지막 이동은 `1칸` 또는 `2칸`이므로 다음과 같은 점화식(递推关系)을 얻을 수 있다.
* `f(x) = f(x - 1) + f(x - 2)`
* 초기값은 `f(0) = 1`, `f(1) = 1`로 설정할 수 있다.
* 처음에는 `dp` 배열을 사용하여 이전 결과를 저장했지만, 현재 값은 항상 **직전 두 값만 필요**하므로 배열을 제거하고 변수 두 개만 사용하는 방식으로 공간을 최적화했다.

**### 개선점**

* 조합 풀이에서 분자와 분모를 각각 먼저 계산하면 **중간 계산값**이 최종 결과보다 훨씬 커질 수 있어 Integer Overflow(整数溢出)가 발생할 수 있다.
* 이 문제에서는 조합 풀이보다 점화식이 명확한 DP 풀이가 적절하다.
* DP 배열을 사용할 경우 시간복잡도(Time Complexity / 时间复杂度)는 `O(n)`, 공간복잡도(Space Complexity / 空间复杂度)는 `O(n)`이다.
* `f(x)`가 `f(x-1)`, `f(x-2)`만 필요하므로 이전 두 값만 유지하면 공간복잡도를 `O(1)`로 최적화할 수 있다.
* 배열 대신 변수 두 개를 사용하여 **Rolling Array(滚动数组)** 방식으로 구현할 수 있다.

**### 배운 점**

* 같은 문제라도 **조합(组合)**, **Dynamic Programming(动态规划)** 등 여러 관점으로 접근할 수 있다.
* 조합 계산에서는 최종 결과가 작더라도 **중간 계산값에서 Integer Overflow(整数溢出)**가 발생할 수 있다.
* DP에서는 먼저 **상태(State / 状态)**를 정의하고, 이전 상태에서 현재 상태로 어떻게 전이되는지 점화식을 찾는 것이 중요하다.
* `f(x) = f(x-1) + f(x-2)`는 마지막 행동이 무엇인지 기준으로 경우를 나누어 얻을 수 있다.
* DP는 반드시 배열을 사용할 필요가 없으며, **이전 상태 중 필요한 값만 유지**하여 공간을 줄일 수 있다.
* `Climbing Stairs`는 Fibonacci Sequence(斐波那契数列)와 같은 형태의 점화식을 가진다.
* 시간복잡도(Time Complexity / 时间复杂度): `O(n)`
* 공간복잡도(Space Complexity / 空间复杂度): `O(1)`
