## 0125. Valid Palindrome (26.8.5)

### 유형
- String
- Two Pointers

### 처음 풀이
- 문자열을 순회하며 알파벳과 숫자가 아닌 문자를 `erase()`로 삭제
- 대문자를 소문자로 변환한 뒤 문자열을 뒤집어 비교
- `"A man, a plan, a canal: Panama"`에서 오답 발생

### 문제점
- `erase()`로 문자를 삭제하면 문자열 길이가 줄어들어 다음 문자를 건너뛰는 문제가 발생
- 문자열을 수정하면서 순회하는 방식은 인덱스 관리가 어려움

### 최적 풀이
- Two Pointers
- O(n), O(1)

### 핵심 아이디어
- 왼쪽과 오른쪽 포인터를 사용한다.
- 영문자와 숫자가 아닌 문자는 건너뛴다.
- `tolower()`로 대소문자를 무시하고 비교한다.
- 문자가 다르면 `false`, 끝까지 비교하면 `true`를 반환한다.

### 배운 점
- 문자열을 순회하면서 `erase()`를 사용하는 것은 인덱스가 변경되어 위험하다.
- `isalnum()`으로 영문자와 숫자를 판별할 수 있다.
- `tolower()`를 이용하면 대소문자를 쉽게 통일할 수 있다.
- `string`은 `size()`와 `length()`가 동일한 기능을 한다.
- `string reversed(s.rbegin(), s.rend());`로 문자열을 간단하게 뒤집을 수 있다.
- `while (left < right && !isalnum(s[left]))`처럼 `left < right`를 먼저 검사하여 범위를 벗어난 접근을 방지해야 한다.
- 안쪽 `while`에서 포인터가 이동할 수 있으므로, 비교 전 `if (left < right)`를 다시 확인하는 이유를 이해했다.


## 0344. Reverse String (26.8.6)

### 유형

* String
* Two Pointers

### 처음 풀이

* 문자열의 양 끝을 가리키는 `left`, `right` 포인터를 사용
* 임시 변수 `temp`를 이용하여 두 문자를 교환
* `left++`, `right--`를 반복하며 가운데까지 이동

### 최적 풀이

* Two Pointers
* O(n), O(1)

### 핵심 아이디어

* 문자열의 양 끝에서 시작하여 가운데로 이동한다.
* `left < right`인 동안 두 문자를 교환한다.
* 한 번의 순회로 문자열을 뒤집을 수 있다.
* 추가 배열을 사용하지 않아 In-place 방식으로 문제를 해결한다.

### 배운 점

* 문자열을 뒤집는 가장 효율적인 방법은 Two Pointers를 사용하는 것이다.
* 임시 변수(`temp`)를 이용해 두 원소를 직접 교환할 수 있다.
* `swap(s[left], s[right])`를 사용하면 같은 기능을 더 간결하게 구현할 수 있다.
* `swap()`의 내부 원리는 임시 변수를 이용한 값 교환과 동일하다.
* 문제에서 **In-place**를 요구하면 새로운 배열을 생성하지 않고 원본 배열을 직접 수정해야 한다.
* 배열을 한 번만 순회하므로 시간 복잡도는 `O(n)`이며, 임시 변수 하나만 사용하므로 공간 복잡도는 `O(1)`이다.


## 0014. Longest Common Prefix (26.8.6)

### 유형

* String
* Vertical Scanning (세로 방향 스캔)

### 처음 풀이

* 공통 접두사의 길이를 1부터 하나씩 증가시키며 비교
* `substr()`를 이용하여 각 문자열의 접두사를 비교
* `longest` 길이의 접두사가 모두 같으면 계속 진행하고, 다르면 이전 길이를 반환하려고 구현

### 문제점

* `size`를 함수가 아닌 변수처럼 사용하여 `size()`를 호출하지 않아 컴파일 오류가 발생했다.
* `substr(longest)`를 사용하여 접두사가 아닌 **longest 위치 이후의 문자열**을 비교하는 실수를 했다.
* 반복문 종료 후 `longest` 값이 이미 1 증가한 상태이므로 반환 길이 계산(`longest - 1`)을 이해하는 데 어려움이 있었다.
* `substr()`로 문자열을 계속 생성하며 비교하여 불필요한 연산이 발생했다.

### 최적 풀이

* Vertical Scanning (세로 방향 스캔)
* O(mn), O(1)

### 핵심 아이디어

* 첫 번째 문자열을 기준으로 각 인덱스의 문자를 선택한다.
* 같은 위치의 문자가 모든 문자열에서 동일한지 확인한다.
* 어떤 문자열이 먼저 끝나거나 문자가 다르면 그 이전까지가 최장 공통 접두사이다.
* `substr(0, i)`를 반환하여 공통 접두사를 얻는다.

### 배운 점

* `size`는 멤버 변수가 아니라 함수이므로 반드시 `size()`로 호출해야 한다.
* `substr(pos)`는 `pos`부터 끝까지의 문자열을 반환하고, `substr(0, len)`은 앞에서부터 `len`개의 문자열을 반환한다.
* `substr()`를 반복해서 생성하기보다 문자 하나씩 비교하는 것이 더 효율적이다.
* `i == strs[j].size()`를 먼저 검사하여 문자열 범위를 벗어난 접근을 방지해야 한다.
* `string::size()`의 반환형은 `size_t`이지만, LeetCode에서는 `int`를 사용해도 대부분 문제없이 동작한다.
* 같은 이름의 함수를 매개변수만 다르게 정의하는 것을 **함수 오버로딩(Function Overloading)** 이라고 하며, 전달되는 인자의 개수와 타입에 따라 적절한 함수가 호출된다.
* 가로 방향 스캔(Horizontal Scanning)과 세로 방향 스캔(Vertical Scanning)의 차이를 이해했다.
* 이 문제에서는 세로 방향 스캔이 가장 직관적이며 구현도 간단하다.


## 0058. Length of Last Word (26.8.7)

### 유형

* String
* Reverse Traversal (역방향 탐색)

### 처음 풀이

* 문자열의 마지막 인덱스부터 앞으로 이동하며 마지막 단어를 찾았다.
* `isalpha()`를 사용하여 알파벳인지 확인했다.
* 마지막 단어의 첫 문자를 찾은 후 내부 `for`문을 추가하여 단어의 길이를 계산했다.
* 공백을 만나면 지금까지 계산한 `wordLen`을 반환하도록 구현했다.

### 문제점

* 문제 조건인 `s`가 **영문자와 공백 `' '`만으로 구성된다**는 점을 충분히 활용하지 않았다.
* 따라서 `isalpha()`를 사용할 필요 없이 `s[i] != ' '`만 확인하면 된다.
* 마지막 단어를 찾는 반복문과 길이를 계산하는 반복문을 중첩하여 코드가 불필요하게 복잡해졌다.
* 문제에서 `s`에 **최소 하나의 단어가 반드시 존재한다**고 보장하므로 불필요한 예외 상황을 고려할 필요가 없다.
* 문제의 제약조건을 먼저 확인하면 구현을 더 단순하게 만들 수 있었다.

### 최적 풀이

* Reverse Traversal (역방향 탐색)
* O(n), O(1)

### 핵심 아이디어

* 문자열의 마지막 인덱스부터 탐색한다.
* 문자열 끝에 존재하는 공백들을 먼저 건너뛴다.
* 마지막 단어를 만나면 공백을 만나거나 문자열의 시작을 넘어갈 때까지 문자의 개수를 센다.
* 계산한 길이를 바로 반환한다.

### 배운 점

* 문제를 풀기 전에 **제약조건(Constraints, 限制条件)**을 자세히 확인하는 것이 중요하다.
* `s`가 영문자와 공백만 포함하므로 `isalpha()` 대신 `' '`인지 직접 비교하면 된다.
* `s`에 최소 하나의 단어가 존재하므로 뒤쪽 공백을 제거하는 과정에서 모든 문자를 지나 `i == -1`이 되는 상황은 발생하지 않는다.
* 반면 마지막 단어가 문자열의 처음부터 시작할 수 있으므로 단어 길이를 계산할 때는 `i >= 0` 검사가 필요하다.
* 문자열의 마지막 부분에 관심이 있는 문제에서는 앞에서부터 탐색하기보다 **역방향 탐색(Reverse Traversal, 逆向遍历)**을 고려할 수 있다.
* 중첩 반복문을 사용하기 전에 하나의 인덱스를 계속 이동시키는 방식으로 더 단순하게 구현할 수 있는지 확인한다.


## *0028. Find the Index of the First Occurrence in a String (26.8.7)

### 유형

* String
* String Matching (문자열 매칭)
* KMP Algorithm

### 처음 풀이

* `haystack`의 각 위치에서 `substr()`을 이용해 `needle` 길이만큼 문자열을 잘랐다.
* 잘라낸 문자열과 `needle`이 같으면 해당 시작 인덱스를 반환했다.
* 찾지 못하면 `-1`을 반환했다.

```cpp
for(int i = 0; i <= haystack.size() - needle.size(); i++){
    if(haystack.substr(i, needle.size()) == needle){
        return i;
    }
}
```

### 문제점

* `substr()`을 반복해서 생성하고 문자열을 비교하므로 최악의 경우 **O(nm)** 시간이 필요하다.
* 문자열이 길고 같은 패턴이 반복되면 이미 비교한 문자들을 다시 비교하게 된다.
* 문제의 제한에서는 브루트포스로도 통과하지만, 효율적인 문자열 검색을 위해 KMP를 사용할 수 있다.

### 최적 풀이

* KMP (Knuth-Morris-Pratt)
* O(n + m), O(m)

### 핵심 아이디어

* `pi[i]`는 `needle[0...i]`에서 **앞부분과 뒷부분이 일치하는 최대 길이**를 저장한다.
* 비교 중 문자가 다르면 처음부터 다시 비교하지 않고 `pi`를 이용해 재사용 가능한 위치로 이동한다.

```cpp
j = pi[j - 1];
```

* `j`는 **현재까지 일치한 문자의 개수**이다.
* 따라서 일치한 부분의 마지막 인덱스는 `j - 1`이므로 `pi[j - 1]`을 사용한다.

```text
j = 3

일치한 문자: index 0, 1, 2
마지막 index = j - 1 = 2
```

### KMP 탐색

```cpp
for(int i = 0, j = 0; i < hSize; i++){
    while(j > 0 && haystack[i] != needle[j]){
        j = pi[j - 1];
    }

    if(haystack[i] == needle[j]){
        j++;
    }

    if(j == nSize){
        return i - nSize + 1;
    }
}
```

* `i` = `haystack`에서 현재 검사하는 문자 위치
* `j` = `needle`에서 현재까지 일치한 문자 개수
* 같으면 `j++`
* 다르면 `j = pi[j - 1]`
* `j == nSize`이면 `needle` 전체를 찾은 것이므로 시작 위치를 반환한다.

### 헷갈렸던 부분

* 브루트포스에서는 `i`가 **needle을 대보기 시작하는 위치**이므로:

```cpp
i <= hSize - nSize
```

* KMP에서는 `i`가 **haystack의 현재 문자 위치**이므로 마지막 문자까지 확인해야 한다.

```cpp
i < hSize
```

* KMP에서는 `i`가 뒤로 가지 않고 `j`만 `pi` 배열을 이용해 이동한다.
* `pi` 배열을 만드는 과정에서도 같은 원리를 사용한다. 이미 계산한 앞뒤 일치 정보를 재사용하여 `pi`를 O(m)에 계산한다.

### 배운 점

* 단순 문자열 매칭은 브루트포스로 **O(nm)**에 해결할 수 있다.
* KMP는 이미 비교한 정보를 `pi` 배열에 저장하여 **O(n+m)**에 문자열을 검색한다.
* `pi` 배열은 문자열의 앞부분과 뒷부분이 얼마나 겹치는지를 나타낸다.
* `j`는 인덱스가 아니라 **현재까지 일치한 길이**라고 생각하면 이해하기 쉽다.
* `j - 1`은 현재까지 일치한 부분의 마지막 인덱스이다.
* 브루트포스와 KMP에서는 `i`가 의미하는 것이 다르므로 반복문의 범위도 다르다.
* KMP의 핵심은 **`i`는 계속 앞으로 이동하고, 불일치가 발생하면 `j`만 `pi`를 이용해 뒤로 이동하는 것**이다.


## 0392. Is Subsequence (26.8.13)

### 유형

* String
* Two Pointers (双指针)
* Greedy (贪心)

### 처음 풀이

* `s`와 `t`를 가리키는 두 개의 인덱스를 사용했다.
* `t`를 앞에서부터 순회하면서 `s`의 현재 문자와 같으면 `sIdx`를 증가시켰다.
* `s`의 모든 문자를 찾으면 `true`를 반환했다.

```cpp
int sIdx = 0, tIdx = 0;

while(tIdx < t.size()){
    if(s[sIdx] == t[tIdx]){
        sIdx++;
    }

    tIdx++;

    if(sIdx == s.size()) return true;
}

return false;
```

---

### 왜 Greedy인가?

`t`에서 필요한 문자를 발견했을 때 **가장 앞에 있는 문자를 바로 선택**한다.

앞의 문자를 선택할수록 뒤에 더 많은 문자가 남기 때문에 손해가 없다.

따라서:

```text
현재 필요한 문자 발견
→ 바로 선택
→ 다음 문자 탐색
```

하는 Greedy(贪心) 방식이 가능하다.

---

### 최적 풀이

* Two Pointers (双指针)
* 시간복잡도: **O(n + m)**
* 공간복잡도: **O(1)**

---

### 헷갈렸던 부분

* 빈 문자열 `s = ""`는 항상 `t`의 부분수열이므로 `true`이다.

---

### Follow-up: 많은 `s`를 검사하는 경우

`t` 하나에 대해 수많은 `s`를 검사한다면 매번 `t`를 처음부터 탐색하는 것은 비효율적이다.

이 경우 `t`를 미리 전처리(预处理)하여:

```text
현재 위치에서
다음 a는 어디?
다음 b는 어디?
다음 c는 어디?
...
```

를 저장해두고 바로 다음 문자 위치로 이동할 수 있다.

현재 단계에서는 **전처리 DP 구현보다 Two Pointers 풀이를 확실하게 이해하는 것이 우선**이다.

---

### 배운 점

* Subsequence(子序列)는 **문자의 순서가 유지**되어야 한다.
* 두 문자열을 순서대로 비교하는 문제에서 Two Pointers를 사용할 수 있다.
* `sIdx`는 현재 찾아야 할 문자, `tIdx`는 탐색 중인 위치를 나타낸다.
* 문자가 같으면 `sIdx++`, 다르면 `tIdx`만 이동한다.
* 가장 앞에서 발견한 문자를 선택하는 Greedy 방식이 최적이다.
* 시간복잡도는 **O(n + m)**, 공간복잡도는 **O(1)** 이다.
* 같은 `t`에 대해 매우 많은 `s`를 검사한다면 `t`를 미리 전처리하는 방법을 사용할 수 있다.
