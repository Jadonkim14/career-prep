# Chapter 10 — System-Level I/O

## 1. Unix I/O

Unix에서는 파일을 **byte sequence(字节序列)** 로 본다.

```text
Regular File
Directory
Character Special File
Block Special File
FIFO
Socket
```

장치도 파일처럼 다룰 수 있으며, 기본 I/O 인터페이스는 다음과 같다.

```c
open()
close()
read()
write()
lseek()
```

## 2. File Descriptor

`open()`은 **file descriptor, fd(文件描述符)** 를 반환한다.

```text
0 → stdin
1 → stdout
2 → stderr
```

fd는 프로세스가 열린 파일을 식별하기 위해 사용하는 작은 정수이다.

```text
Process
→ Descriptor Table
→ Open File Table
→ File / Vnode
```

## 3. `read()` / `write()`

```c
read(fd, buf, n);
write(fd, buf, n);
```

항상 요청한 `n` byte를 처리하는 것은 아니다.

```text
return > 0 → 실제 처리한 byte 수
return = 0 → EOF(read)
return < 0 → error
```

요청보다 적게 처리되는 것을 **Short Count(短计数)** 라고 한다.

## 4. File Sharing

프로세스의 fd는 **open file entry**를 가리킨다.

Open file entry에는 대표적으로:

```text
File Position
Reference Count
Access Mode
```

등의 상태가 있다.

같은 파일을 `open()` 두 번 하면 일반적으로 서로 다른 open file entry가 만들어져 file position도 독립적이다.

## 5. `dup()` / `dup2()`

`dup()` 또는 `dup2()`를 사용하면 여러 fd가 같은 open file entry를 가리킬 수 있다.

```text
fd1 ─┐
     ├→ Same Open File Entry
fd2 ─┘
```

따라서 **file position도 공유**한다.

이 원리를 이용하면 shell의 I/O redirection을 구현할 수 있다.

```c
dup2(fd, STDOUT_FILENO);
```

```text
stdout
→ terminal 대신 file로 연결
```

## 6. `fork()`와 File Descriptor

`fork()` 후 parent와 child는 각각 descriptor table을 가지지만, 기존 fd들은 같은 open file entry를 가리킨다.

```text
Parent fd ─┐
           ├→ Same Open File Entry
Child fd ──┘
```

따라서 parent와 child는 **file position을 공유**한다.

## 7. Standard I/O

C Standard I/O(标准I/O)는 `FILE *` 기반의 고수준 I/O이다.

대표 함수:

```c
fopen()
fclose()
fread()
fwrite()
fgets()
fprintf()
```

`FILE *`는 개념적으로:

```text
File Descriptor
+
Memory Buffer
```

를 관리하는 stream abstraction이다.

---

## 8. Buffered I/O

Standard I/O는 **buffer(缓冲区)** 를 사용하여 system call 횟수를 줄인다.

```text
Application
→ User-space Buffer
→ write()
→ Kernel
```

예를 들어 여러 번 `printf()`를 호출해도 실제 `write()`는 한 번만 발생할 수 있다.

```c
fflush()
```

를 사용하면 buffer의 데이터를 강제로 출력할 수 있다.

## 9. Unix I/O vs Standard I/O

```text
Standard I/O
→ 일반 파일 / 텍스트 처리에 편리
→ buffering 제공

Unix I/O
→ low-level 제어
→ metadata 접근
→ signal handler에서 사용할 수 있는 함수 존재
```

원칙은:

> 가능한 경우 높은 수준의 I/O 함수를 사용한다.

## 10. RIO — Robust I/O

RIO(健壮I/O)는 short count를 안전하게 처리하기 위한 wrapper이다.

```text
Unbuffered RIO
├─ rio_readn()
└─ rio_writen()

Buffered RIO
├─ rio_readlineb()
└─ rio_readnb()
```

특히 network socket에서 유용하다.

## 11. `rio_readn()`

`rio_readn()`은 원하는 byte 수를 읽을 때까지 반복해서 `read()`한다.

```text
read() → short count
→ 남은 byte 다시 read()

read() → EINTR
→ 다시 read()

read() → 0
→ EOF
```

```c
nleft -= nread;
bufp += nread;
```

를 통해 남은 크기와 buffer 위치를 계속 갱신한다.

## 12. Buffered RIO

Buffered RIO는 `rio_t` 구조체로 내부 buffer 상태를 관리한다.

```c
typedef struct {
    int rio_fd;
    int rio_cnt;
    char *rio_bufptr;
    char rio_buf[RIO_BUFSIZE];
} rio_t;
```

```text
rio_fd
→ descriptor

rio_cnt
→ 아직 읽지 않은 byte 수

rio_bufptr
→ 다음 unread 위치

rio_buf
→ 내부 buffer
```

## 13. Binary File

Binary file(二进制文件)는 임의의 byte sequence이다.

따라서 binary data에는 문자열 함수 사용을 조심해야 한다.

```text
strlen()
strcpy()
fgets()
```

등은 `\0`이나 newline 같은 값을 특별하게 처리한다.

Binary data에는 보통:

```c
read()
write()
fread()
fwrite()
rio_readn()
```

처럼 byte 수를 명시하는 방식을 사용한다.

```text
File Size
File Type
Permission
```

```c
st.st_size
st.st_mode

S_ISREG()
```

## 15. Directory I/O

Directory는 다음 함수로 순회한다.

```c
opendir()
readdir()
closedir()
```

```text
opendir()
→ directory 열기

readdir()
→ entry 하나씩 읽기

closedir()
→ directory 닫기
```

`struct dirent`는 각 directory entry의 정보를 가진다.

## 16. 핵심 정리

```text
File
→ Byte Sequence

open()
→ fd 반환

fd
→ Descriptor Table
→ Open File Table
→ File

read/write
→ Short Count 가능

dup / dup2
→ Open File Entry 공유

fork
→ Parent/Child가 Open File Entry 공유

Standard I/O
→ FILE * + Buffer

RIO
→ Robust Short Count 처리

stat/fstat
→ Metadata

opendir/readdir/closedir
→ Directory Access
```

**Chapter 10의 핵심은 결국 `fd → open file entry → kernel file` 구조와, 그 위에서 Unix I/O / Standard I/O / RIO가 어떻게 동작하는지를 이해하는 것**이다.
