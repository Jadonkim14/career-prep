# V0.1 — C 기반 Event Engine

## 목표

가상의 LoL 경기 이벤트 데이터를 C로 읽고 분석하는 기본 이벤트 엔진(Event Engine, 事件引擎)을 구현한다.

Beej's Guide to C Ch.2~12에서 학습한 개념을 실제 프로젝트에 적용하는 첫 단계이다.

## 구현 기능

- 경기 이벤트 파일 파싱(Parsing, 解析)
- `Event` 구조체(Struct, 结构体)를 이용한 데이터 표현
- `malloc()` / `realloc()`을 이용한 동적 메모리 할당(Dynamic Memory Allocation, 动态内存分配)
- 이벤트 수에 따른 동적 배열(Dynamic Array, 动态数组) 확장
- BLUE / RED Kill 및 Dragon 통계 계산
- 특정 시간대의 이벤트 조회
- 간단한 Critical Moment 탐지
- 명령행 인자(Command-Line Arguments, 命令行参数)를 통한 파일 입력
- `free()` / `fclose()`를 통한 자원 해제

## Critical Moment 탐지

V0.1에서는 간단한 규칙 기반(Rule-Based, 基于规则) 탐지 방식을 사용한다.

Critical Moment 조건:

1. 같은 팀이 30초 이내에 연속으로 2번 사망
2. 두 `DEATH` 이벤트가 연속으로 발생
3. 직후 상대 팀이 `BARON`, `DRAGON`, `TOWER` 중 하나를 획득

예시:

```text
1511 RED DEATH
1520 RED DEATH
1532 BLUE BARON
````

출력:

```text
Critical Moment #1
25:11 ~ 25:32
2 Deaths -> BARON Lost
```

## 테스트

다음 항목을 테스트했다.

* 정상 경기 파일 파싱
* 동적 배열 확장: `4 → 8 → 16 → 32`
* Kill / Dragon 통계 계산
* 특정 시간대 이벤트 조회
* BARON / DRAGON / TOWER Critical Moment 탐지
* Critical Moment가 없는 경우
* 잘못된 파일 경로 처리
* `gcc -Wall -Wextra -pedantic` 기준 경고(Warning, 警告) 없이 컴파일

## 현재 한계

* 실제 Riot API가 아닌 가상의 경기 데이터를 사용
* 입력 데이터가 올바른 형식이며 시간순으로 정렬되어 있다고 가정
* Critical Moment 탐지가 연속된 이벤트에 의존
* 잘못된 입력에 대한 별도의 유효성 검사(Validation, 有效性检查)가 없음
* 실제 Replay 및 GUI는 아직 구현하지 않음

## V0.1에서 틀렸거나 헷갈렸던 내용

- C에는 `using namespace std;`가 없다.

- C에서 파일 열기/닫기:
  ```c
  FILE *fp;
  fp = fopen("match.txt", "r");
  fclose(fp);
  ```

- `fgets()`로 파일을 한 줄씩 읽기:
  ```c
  while (fgets(s, sizeof s, fp) != NULL)
  ```

- C 문자열 끝에는 `'\0'`이 필요하다. 직접 문자를 복사해서 문자열을 만들었다면 마지막에 추가해야 한다.
  ```c
  e.team[j] = '\0';
  e.event[k] = '\0';
  ```

- C에 `string` 타입은 없지만, `printf()`에서 `%s`는 C 문자열을 출력할 때 사용한다.
  ```c
  printf("%c\n", e.team[0]);  // 문자
  printf("%s\n", e.team);     // 문자열
  ```

- `printf()`에서 형식 지정자와 값을 대응시킨다.
  ```c
  printf("time=%d team=%s event=%s\n",
         e.time, e.team, e.event);
  ```

- 문자열의 내용을 `==`, `!=`로 비교하지 않는다. `strcmp()`를 사용한다.
  ```c
  strcmp(events[i].event, "KILL") == 0
  ```

  `strcmp()`의 결과가 `0`이면 두 문자열이 같다.

- `realloc()`의 크기는 원소 개수가 아니라 **byte 단위**다.
  ```c
  realloc(events, sizeof(Event) * new_capacity);
  ```

- 명령행 인자:
  ```c
  int main(int argc, char *argv[])
  ```

  ```bash
  ./lolreview match.txt
  ```

  이면:

  ```text
  argc = 2
  argv[0] = "./lolreview"
  argv[1] = "match.txt"
  ```

  - `argc` = argument count → 명령행 인자의 개수
  - `argv` = argument vector → 명령행 인자들을 저장한 배열

- `char *argv[]`는 **`char *`를 원소로 가지는 배열**이다. 각 `char *`는 문자열 하나를 가리킨다.

  ```text
  argv[0] → "./lolreview"
  argv[1] → "match.txt"
  ```

  따라서:

  ```c
  argv[1]       // "match.txt"
  argv[1][0]    // 'm'
  argv[1][5]    // '.'
  ```
